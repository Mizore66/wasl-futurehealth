## 1. IFHAS screening is coded results, not a Gemma reader

Reader B for `ifhas-screen` is the deterministic coded LOINC/UCUM string (`coded_lab`), and reader A is a regex over the printed panel. No language model reads these items, so they are reported separately and excluded from the Gemma figures below.

- Agreed screening panels: 28 (of 30). Reader A (panel regex) matched the key on **6/28**; coded reader B matched the key's `coded_label` on **28/28**, including the 2 items whose key coded_label is itself `unavailable` (coded parsing is deterministic code, not a model).
- Guide/panel mismatch: the labelling guide requires a **random** glucose, but **27/30** panels say fasting. Reader A's regex reads only random-glucose wording, so it returned `glyc=X` on **26/28** agreed panels; on **21** of them the key holds a real glyc value, not X (keyed glyc distribution: {'D': 4, 'N': 14, 'P': 4, 'S': 1, 'X': 5}). The guide and key were frozen and are not changed; this is a disclosed limitation of the test, not a reader fix. (Reader A also returned glyc=X on both unadjudicated panels, which have no key.)
- Reader-B unavailable on screening: 2 (implausible coded value under its unit; see section 4).

4 agreed-but-wrong answers: **1 closing-direction**, **3 holding-direction**. A closing-direction error is one where both readers resolve a loop the key says is not resolved; a holding-direction error keeps the loop open but names the wrong state or fails to route a wrong-kind document to a human.

| f2l-021 | ldct-workup | indeterminate | wk_incomplete | holding |
| f2l-029 | ldct-workup | wk_surveillance | wk_incomplete | holding |

- **f2i-031**: CLOSING direction. Key bp=pending (home BP monitoring requested, 'No medication commenced today; decision deferred pending home readings'); both readers said bp=managed, so the loop would be closed while the key says it is still pending. This is the one agreed-but-wrong answer that could close a loop that should stay open.
- **f2l-002**: HOLDING direction, wrong kind. A pneumonia discharge summary with no lung-cancer work-up content; key indeterminate (a human should see it). Both readers confidently said wk_incomplete, which keeps the loop open but does not route it to review and mislabels an unrelated document as an incomplete work-up.
- **f2l-021**: HOLDING direction, wrong kind. A smoking-cessation review that only mentions the nodule in passing; key indeterminate. Both readers said wk_incomplete: the loop stays open, but the document was not recognised as the wrong kind of note.
- **f2l-029**: HOLDING direction. MDT outcome with a stated CT surveillance plan (a decision, not 'pending'); key wk_surveillance. Both readers said wk_incomplete, so a surveillance plan is held as an incomplete work-up. The loop stays open but the wrong follow-up path would be started.

This is a count of four on 113 agreed items for synthetic text. It is not a rate of unsafe closure on real patients, and a count of one closing-direction error means the zero-error claim cannot be made.
