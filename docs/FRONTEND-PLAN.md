# Wasl frontend: stack, plan and verification cycle

Owner: Kai (frontend). Design source: the canvas "Wasl — Design Directions" (https://claude.ai/artifact/EGwokmQboHejaTqUdjRq74). Backend contract: [`API.md`](API.md).

## Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | Next.js 16 App Router, React 19, TypeScript strict, pnpm. `cacheComponents` off. | Server components read the API or the fixtures with no client fetch code; one deploy for app, site and phones. Cache Components (the v16 template default) would force a `<Suspense>` around every per-request read and around the shell's `usePathname`, which six parallel screen owners would each trip over. |
| Styling | Tailwind CSS v4 with CSS-variable tokens from the canvas (`achromatic-ledger`) | The canvas is already token-driven; v4 `@theme` maps the tokens one to one. |
| Components | shadcn/ui (Radix primitives), copied into `web/components/ui` | Accessible dialogs, tabs, toggles and tooltips we own and restyle; no theme to fight. |
| Motion | `motion` (Framer Motion) for layout and presence; `@number-flow/react` for ticking totals | The pipeline replay is rows arriving, fields resolving and counters ticking. `layout` + `AnimatePresence` do this without hand-rolled timers. Respect `prefers-reduced-motion` via `MotionConfig reducedMotion="user"`. |
| Charts | Hand SVG (tracks, bars, per-seed dots) | The canvas has four simple charts. A chart library costs more than it saves. |
| Data boundary | `zod` schemas for every endpoint, parsed once in `web/lib/api` | The API is the only untrusted input. Everything past the parser is typed. |
| Fonts | `next/font`: Geist, Geist Mono, IBM Plex Sans Arabic | As specified by the canvas. |
| i18n (phones) | Plain typed dictionaries per language, `dir` per locale | Four short screens do not need an i18n framework. |
| Tests | Vitest (schemas, adapters, replay timeline), Playwright (routes, clicks, screenshots), `@axe-core/playwright` | See the verification cycle. |

Rejected: Storybook (the canvas is the component catalogue), TanStack Query (RSC fetch plus one server action for review covers it), Recharts/visx (too heavy for four SVGs), next-intl (overkill for four phone screens).

## Data shapes first

```
web/lib/api/schema.ts     zod: Meta, CaseSummary, CaseDetail, Audit, Dashboard, Fixtures, ReviewRequest
web/lib/api/source.ts     getDashboard(), getCases(q), getCase(id), getAudit(id), postReview(...)
                          WASL_API_URL set → live Go API; unset → docs/api-samples (copied to web/data/api)
web/lib/domain/*.ts       pure functions: caseStage(case) → 8-step pipeline stage, dayToDate(day), kpiGap(dashboard)
web/data/replay.json      generated by web/scripts/build-replay.ts from pipeline/results/showcase/*  (pnpm gen)
web/data/results.json     generated from pipeline/results/final/SUMMARY.md and docs/BRIEF.md evidence table
web/data/people.json      display names per registration (see gap G1)
```

The pipeline replay is a **pure reducer over a scripted event list**: `step(state, event) → state`. The UI only renders state and owns the timer. That makes the replay testable without a browser, and Pause/Step trivial.

## Phases (each ends in a check)

1. **Foundation.** Scaffold `web/`, tokens, fonts, app shell (240px sidebar, nav, synthetic-data chip), `lib/api` with schemas, fixtures mode, generators for `replay.json` / `results.json` / `people.json`, Vitest + Playwright harness. **Check:** every file in `docs/api-samples` parses; `/app` renders the shell; `pnpm verify` green.
2. **Screens in parallel**, one owner per route folder, no shared files edited:
   - Programme + Results;
   - Today + Patient + Referrals;
   - Review (with the real POST);
   - Pipeline replay + Matching + Reading;
   - Site pages (landing, how it works, experts);
   - Patient phones (RTL).

   **Check per screen:** Playwright opens the route, walks every click from the canvas, asserts the key numbers against `results.json` / API, saves a screenshot, axe has no serious violations.
3. **Integration.** Run against the live Go API (`scripts/demo.sh serve`). **Check:** same Playwright suite with `WASL_API_URL` set.
4. **Demo polish.** Record the 3-minute script path as one Playwright test that produces the video (`video: 'on'`).

## Verification cycle

`pnpm verify` = `tsc --noEmit` → `eslint` → `vitest run` → `next build` → `playwright test`.

- **Schema tests** parse every `docs/api-samples/*.json`. A backend change that breaks the contract fails here first.
- **Domain tests** pin the honest numbers: 0/2,090 false closures, 25,620 decisions, 1,741 chains, KPI 12.4 / 32.0 / 33.0 (demo cohort) and 13.0 / 29.4 / 32.7 (held-out). A screen that shows a number not in `results.json` is a bug.
- **Replay tests** step the reducer through one full loop and assert totals never exceed the source totals and the loop returns to state 0.
- **E2E** per route: renders, clicks, screenshot to `web/test-results/screens/`. Review POST asserts 201 and the 403 for a wrong role.
- **Honesty lint** (`web/scripts/honesty.ts`): every route renders a data-mode label (`Synthetic data` / `Replay` / `Simulated`).
- Screenshots are compared by eye against the canvas boards at the end of each phase.
