# Exact-version licence review: 128 empty scanner results

## Scope and conclusion

This review covers **exactly the 128 records** in `supply-chain/licenses.json` whose `licenses` array is empty. All 128 are npm packages from `web/pnpm-lock.yaml`; they are 128 distinct name+version pairs. Each was checked at the exact locked version against its npm registry manifest and its exact registry tarball.

**All 128 package-level declarations were established; none is unresolved.** This is an evidence review of the scanned npm package artifacts, not legal clearance and not an exhaustive audit of every native or bundled third-party component. The scanner evidence itself was not changed.

## Methodology

1. Parsed `supply-chain/licenses.json` and selected only `packages[]` with an empty `licenses` array. Asserted 128 records and 128 unique `(name, version)` pairs, all targeting `web/pnpm-lock.yaml`.
2. Matched each exact `name@version` to its `packages` and `snapshots` keys in `web/pnpm-lock.yaml`; no version was inferred from a range, sibling platform package, or another version.
3. Retrieved the npm packument from `https://registry.npmjs.org/<url-encoded-name>`, selected the exact `versions[version]`, and then independently retrieved `https://registry.npmjs.org/<url-encoded-name>/<version>`. For all 128, the direct exact endpoint agreed on name, version, licence declaration, tarball URL, SHA-512 integrity, and SHA-1 shasum. One non-licence difference was observed for `@tailwindcss/oxide-wasm32-wasi@4.3.3`: the packument/direct endpoints use different `bundledDependencies`/`bundleDependencies` aliases; all licence and artifact evidence agreed.
4. Downloaded the exact `dist.tarball` for every package. Verified all 128 against both registry SHA-512 SRI and SHA-1 shasum. Tarballs and manifests were stored outside the repository, each archive initially in its own new empty numbered directory.
5. Read `package/package.json` and every regular archive member whose basename begins `LICENSE`, `LICENCE`, or `COPYING` (plus `NOTICE`) directly with Python `tarfile`; archives were not extracted and package code was never executed. Collection/analysis scripts lived in a separate temporary directory and were run with `python3 -I`. No containers were run.
6. Used the exact registry declaration as the identifier where the exact archive lacks licence text, as permitted for this review. Where text exists, compared its terms with the declaration. No registry-versus-archive declaration mismatch or contradictory licence text was found. Compound expressions are retained verbatim; absent component texts and bundled-component licences are explicitly noted rather than silently merged.

Primary artifacts were retrieved on **2026-11-10 UTC**. Temporary evidence is not a tracked scanner artifact; the per-row registry and tarball URLs are the durable upstream references.

### Evidence limitations requiring attention

- **77 packages have no matched licence text in their exact tarball.** Their identifiers are nevertheless established by two agreeing exact-version manifests (registry and archived `package.json`), and are marked `Metadata-only` below.
- **Four Sharp packages declare conjunctive expressions but ship only Apache-2.0 text in `package/LICENSE`:** the three Windows packages declaring `Apache-2.0 AND LGPL-3.0-or-later`, and `@img/sharp-wasm32@0.35.5` declaring `Apache-2.0 AND LGPL-3.0-or-later AND MIT`. This is incomplete textual corroboration, not a conflicting grant and not a reason to discard the declared components.
- **`@tailwindcss/oxide-wasm32-wasi@4.3.3` has no root LICENSE**, but contains three bundled `@emnapi/*` MIT texts and a bundled `tslib` text with 0BSD terms. The latter belongs to the separate bundled component and is not silently added to the root package expression.
- No package name, repository default branch, latest release, or sibling package was used as licence evidence.
